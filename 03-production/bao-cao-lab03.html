3a Authentication

Server chạy qua Streamable HTTP tại localhost:8000/mcp, client gửi bearer token. Với token hợp lệ, mọi thứ hoạt động đúng:

terminal 2 — auth_client.py
Tools (có auth):
  - get_weather: Lấy thời tiết hiện tại của một thành phố.

Kết quả: Hanoi: 29°C, trời mưa

README liệt kê ba trạng thái auth. Kiểm chứng bằng cách gửi thẳng HTTP request với từng loại token:

Trường hợpREADME nóiThực tếKết luận
Token hợp lệ200200Khớp
Thiếu token401401Khớp
Token sai403401Lệch

Server trả 401 kèm header WWW-Authenticate: Bearer error="invalid_token" cho cả hai trường hợp thiếu và sai token. Đây là hành vi đúng chuẩn RFC 6750 — 401 dành cho token không hợp lệ, còn 403 dành cho token hợp lệ nhưng thiếu quyền (insufficient scope). README mô tả sai, không phải SDK sai.

Cả hai token trong VALID_TOKENS đều được xác minh: dev-token-abc123 và prod-key-xyz789 cùng trả 200. Đúng như README nói, logic tool không hề biết gì về auth — SDK xử lý toàn bộ ở tầng transport.

3b Tool Registry & Discovery

Lỗi mã nguồn — chặn hoàn toàn

registry_client.py dòng 44 gọi open(path) không chỉ định encoding. Trên Windows, Python dùng codec mặc định theo locale (cp1252) nên vỡ ngay khi đọc tiếng Việt trong registry.json:

UnicodeDecodeError: 'charmap' codec can't decode byte 0x9d in position 192

Vì yêu cầu là không sửa mã nguồn, cách chạy được điều chỉnh thay vì code — bật UTF-8 mode của Python:

PowerShell — 03-production
PS> $env:PYTHONUTF8 = "1"
PS> python registry_client.py

Sau đó output khớp README. Agent liệt kê 4 tool, tìm theo tag weather ra 2 kết quả, và best_match() chọn đúng phiên bản cao hơn:

registry_client.py
--- Agent cần tool có tag "weather" ---
Tìm thấy 2 tool(s):
  • get_weather v1.0.0 (server: weather)
  • get_weather_v2 v2.0.0 (server: weather-v2)

Best match: get_weather_v2 v2.0.0
Kết nối tới server [weather-v2]...
Kết quả: {"api_version": "2.0", "city": "Hanoi", "temp": 29, ...}

Điểm hay của thiết kế này: agent không hề biết trước server nào có tool nào. Nó tra registry theo capability (tag, keyword), rồi connect_and_call() tự chọn đúng transport và gắn token nếu server yêu cầu.

3c Versioning & Backward Compatibility

Output khớp README: client đọc server://info trước, biết get_weather đã deprecated, rồi gọi được cả hai phiên bản.

versioned_client.py
Server: weather-v2 v2.0.0
Deprecated tools: ['get_weather']
Migration: Chuyển từ get_weather sang get_weather_v2…

[v1] get_weather('Hanoi'):
  Hanoi: 29°C, trời mưa

[v2] get_weather_v2('Hanoi', forecast=True):
  { "api_version": "2.0", "temp": 29, "humidity": 82,
    "forecast": [ {"day": "tomorrow", "temp": 27, …} ] }

README khẳng định tham số optional giúp client cũ không bị break. Kiểm chứng bằng cách gọi get_weather_v2 chỉ với city, đúng như một client viết từ thời chưa có v2:

Kiểm chứngKết quả
Gọi thiếu include_forecast và unitsKhông lỗi — units mặc định 'celsius', không có khoá forecast
Schema tự sinh có ghi default không?required: ['city'] — hai tham số mới đều mang default trong schema
units="fahrenheit" có đổi thật không?29°C → 84.2°F, đúng công thức

Điểm đáng chú ý: required chỉ chứa city. Chính vì include_forecast và units có giá trị mặc định trong signature Python mà schema tự đánh dấu chúng là optional — lập trình viên không phải khai báo gì thêm. Đây là cùng một cơ chế tự sinh schema đã thấy ở bài 02, nay phục vụ mục đích tương thích ngược.

Lỗi phát hiện được — đã sửa

Cả ba mục dưới đây đã được vá và chạy lại để xác nhận. Đáng chú ý: sau khi sửa lỗi 1, registry_client.py chạy được với locale mặc định của Windows — không còn cần PYTHONUTF8. Sau khi sửa lỗi 2, nhánh streamable-http gọi tool thành công qua bearer token, trả về Hanoi: 29°C, trời mưa.

Lỗi 1 · chặn chạy · registry_client.py:44

open(path) thiếu encoding="utf-8". Bài lab không chạy được trên Windows nếu không bật UTF-8 mode. Trên macOS/Linux thì không lộ vì locale mặc định đã là UTF-8 — đây là lỗi chỉ xuất hiện trên một nền tảng.

Lỗi 2 · tiềm ẩn · registry_client.py:108

Nhánh streamable-http unpack 3 giá trị từ streamable_http_client(...), nhưng SDK chỉ yield read_stream, write_stream — đúng 2. Trong khi đó auth_client.py unpack 2 và chạy tốt.

Lỗi này không lộ ra khi chạy demo, vì không tool nào trong registry trỏ tới server dùng HTTP. Ép chạy vào nhánh đó thì vỡ ngay:

ép registry_client vào nhánh streamable-http
server 'weather-secure': transport='streamable-http'
url='http://localhost:8000/mcp'

ExceptionGroup: unhandled errors in a TaskGroup
  LOI GOC -> ValueError: not enough values to unpack (expected 3, got 2)
Lỗi 3 · tài liệu · README mục 3a

“Token sai → 403” — thực tế là 401, và 401 mới đúng chuẩn RFC 6750. Nên sửa tài liệu, không sửa code.

Lỗi 2 đáng chú ý về mặt kỹ thuật hơn lỗi 1: nó là dead code chưa từng được chạy. Registry có sẵn server weather-secure dùng HTTP, nhưng cả 4 tool đều trỏ sang server khác, nên nhánh xử lý HTTP không bao giờ được kiểm chứng. Đúng kiểu lỗi chỉ bùng ra ở production khi có tool thật đăng ký qua HTTP.
